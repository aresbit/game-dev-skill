## 2. Loading pipeline end to end

### 2.1 Gate → click → start (A:415–503)

1. A:420 `if (!window.LPWebLoading) showMessage("helper")` — file B must have loaded, else refuse.
2. A:421 `else if (!navigator.gpu)` → WebGPU notice. A:425–433 additionally probes with `navigator.gpu.requestAdapter()`
   (`webgpuReady` promise) because "navigator.gpu alone does not mean it works" (A:411–414). There is **no WebGL2 fallback**.
3. Click on `#front` (A:424, `{once:true}`) → `start()` (A:435). It shows `#load`, calls `setProgress(0)`, builds `config`,
   `LPWebLoading.installDownloadMeter()` (A:477), then injects the Unity loader:
   ```js
   script.src = buildUrl + "/a0a6878ef9d9dce037804e0fe80e6d3c.loader.js";   // A:480
   script.onload = function () { … createUnityInstance(canvas, config, setProgress) … };
   ```
4. `createUnityInstance(...).then(...)` (A:489): stores `window.__lpUnity`, `setProgress(1)`, then after 300 ms adds
   `#front.out` (opacity 0, CSS A:70) and after another 800 ms `display:none` + `canvas.focus()`.

### 2.2 Progress → `正在准备画面 · N%`

`setProgress` (A:369–373) maps the loader's `0..1` value to the UI:

```js
function setProgress(p) {
  var v = Math.max(0, Math.min(100, Math.round(p * 100)));
  shownProgress = v;
  fill.style.width = v + "%"; tip.style.left = v + "%";
  pct.textContent = t("progress") + percent(v);   // zh: "正在准备画面 · " + "N%"
}
```

The label comes from `LP_I18N.langs[lang].text.progress` (A:23; zh = `"正在准备画面 · "`), the number from `percent()`
(A:207–208) which uses a language's own `"percent"` form — **only French** overrides it (`"{0} %"`), all others use `"{0}%"`.
`applyLang()` re-renders the same value when the language changes (A:257). **[FACT]**

The engine drives `d(p)` (the `onProgress`) from `T()` in C — the loader aggregates `downloadProgress`
(C:[5990-6430]): it tracks `dataUrl` + `frameworkUrl` + `codeUrl` + each `.bundle`, and emits
`d(.9 * (started ? (started - notFinished - (lengthComputable ? idx*(total-loaded)/total : 0)) / started : 0))`
(C:[6423]) — i.e. **download is the first 90 %** of the bar; the remaining 10 % is compile/instantiate, then `d(1)`.
Addressables chapter bundles fetched *after* startup are **not** reflected in this bar; the page only shows 0→100 %
during boot. (The custom `__lpNet` meter exists for the in-game chapter bar via `LPWebDownloadLoaded/Pending`.) **[INFER, from C code + A/B]**

### 2.3 Addressables bundles: fetch, cache, CACHE_VERSION, header fixup

- **Catalog** `StreamingAssets/aa/catalog.bin` + `aa/settings.json` (E). settings.json: `m_buildTarget:"WebGL"`,
  `m_SettingsHash:"552ad348dccd3da75e90cb44b7acbdae"`, `m_AddressablesVersion:"4.1.1"`, `m_maxConcurrentWebRequests:3`,
  `m_DisableCatalogUpdateOnStart:false`. **[FACT]**

- **CACHE_VERSION anchor** (B:1–10):
  ```js
  var CACHE_VERSION = "0.1.0+4a120fa1";
  ```
  Comment B:6–9: pinned to the value live when the eight-chapter package shipped (2026-10-11); Unity's `cleanUpCache`
  (C:[6580] `…cleanUpCache()` in `connect()`) evicts entries whose `version != productVersion`, so anchoring on the live
  value keeps returning players' cached chapters. "此后这个值永远不随构建变化". It is passed as
  `productVersion: LPWebLoading.cacheVersion` (A:458) and stored per entry as `metaData.version` (C:[16860] `d.metaData={url,accessedAt:Date.now(),version:d.productVersion}`). **[FACT]**

- **cacheControl** (B:15–21) overrides Unity's default: only hashed bundle files
  (`/StreamingAssets/aa/<x>/<x>_<32hex>.bundle`) and the hashed `.data(.br)` get `"immutable"`; everything else
  (unhashed catalog/settings) is `"no-store"`. Comment B:19: "Unhashed catalogs/settings must never inherit the
  immutable policy." `loader.js` uses `control` to decide revalidation (C:[16880] `if("immutable"==d.control){d.revalidated=!0;updateRequestMetaData…}`). **[FACT]**

- **Decoded-size / `Content-Encoding` header fixup** (B:86–98, B:202–215). Root cause (B:86): *fetch has already
  decoded the body*, but Unity's reader would guess ~2× Brotli size and allocate a second full buffer. So the custom
  fetch wrapper replaces the stream and rewrites headers to the **exact decoded length**:
  ```js
  headers.set("Content-Length", String(expected));   // expected = LPWebDecodedSizes[name]
  headers.delete("Content-Encoding");
  ```
  and re-checks each chunk against `expected`, throwing `"Decoded resource length mismatch: <name>"` on over/under-run
  (B:106, B:110–113). The same fixup is applied on **cache hits** in `installCacheReader` (B:202–215) without a rewrite/clone. **[FACT]**

- **`installDownloadMeter()`** (B:23–134) monkey-patches `window.fetch`; only for same-origin `/StreamingAssets/aa/…`
  bundles and `/Build/<32hex>.data(.br)`. It builds `window.__lpNet = {entries:{name:{loaded,total,done,cached,status,
  attempt,phase,started,lastByteAt,...}}, failed:<url>}`. It also honors **`LPWebBundleTransport`** (B:56–69): when a bundle
  has an alternate representation (`.raw`/`identity`), it rewrites the *network* request to `transport.url` while
  "UnityCache still sees its original URL" (B:58). Non-matching requests pass through unchanged. **[FACT]**

- **`installCacheReader(module)`** (B:156–221), wired via `preRun` (A:460): wraps `UnityCache.prototype.{storeRequest,
  updateRequestMetaData,loadRequest}`. It writes a browser-side content tag `lpContent` (first 16 hex of the bundle's
  sha256, from `LPWebBundleContent`) into the cache metadata, and on read treats a missing/mismatched tag as a **miss**
  (`return undefined`) so the loader re-downloads. Rationale (B:151–155): UnityCache is keyed by URL and with
  `immutable` never revalidates, but a bundle **name**'s hash is over build inputs, so same-name-different-bytes caused a
  permanent CRC failure (the "2026-10-12 王庭 CRC 事故"). Tagging is content-derived, so no future CACHE_VERSION bump is
  needed. Only tags bytes after `Cache.put` succeeds (WeakMap `stores`, B:163–177) to avoid tagging old bytes. **[FACT]**

## 3. JS ↔ engine bridge (`DllImport("__Internal")` / jslib / wasmImports)

All custom glue is Emscripten **jslib**, merged into `framework.js` (D). The wasm **import table** (module `env`) names
them; the C# side is `class WebPlatform` with `[DllImport("__Internal")]` externs (F `names.txt:75173`,
`literals_raw.txt:70668`). Full list + signatures in `reports/web/bridge_functions.txt`. **[FACT]**

Import key → JS impl (`unityFramework` wasmImports map in D, e.g. `"LPWebGetLang":_LPWebGetLang`):

| `LPWebGetLang` | `_LPWebGetLang()` | returns UTF-8 `char*` of `window.__lpLang` (malloc'd) |
| `LPWebSetLang` | `_LPWebSetLang(langPtr)` | `window.__lpSetLang(lang)` else `window.__lpLang = lang` |
| `LPWebCanvasScale` | `_LPWebCanvasScale()` | `canvas.width/canvas.clientWidth` (f64) |

| `LPWebDownloadPending` | `_LPWebDownloadPending(specPtr)` | count of spec entries not `done` |

Per language: `html`, `script` (`latin`/`han`/`kana`/`hangul`), `name`, `browser[]` prefix(es), `logo`, `logoWidth`,
`text{title,hint,intro,progress,webgpu,failed,missing,network,retry,helper}`. **[FACT]**

| code | html | script | browser prefix | logoWidth | percent |
|---|---|---|---|---|---|
| en | en | latin | en | 820 | — |
| fr | fr | latin | fr | 820 | `{0} %` |
| es | es | latin | es | 820 | — |
| de | de | latin | de | 820 | — |
| pt | pt-BR | latin | pt | 820 | — |
| zh | zh-CN | han | zh | 708 | — |
| ja | ja | kana | ja | 820 | — |
| ko | ko | hangul | ko | 820 | — |

**Detection order** (head IIFE A:29–45; A:25–28 prose):
1. saved choice — `localStorage.getItem("lp-lang")`, accepted only if it is a known code (A:31, A:40);
2. else browser prefix — `navigator.languages[0] || navigator.language`, lower-cased, first `LP_I18N` entry whose
   `browser[]` prefix matches `tag.indexOf(prefix)===0` (A:32–39);
3. else `LP_I18N.fallback` = `"en"` (A:40).
Result → `window.__lpLang`; also sets `documentElement.lang`, `data-script`, `document.title` (A:42–44).

**Storage keys**
- `"lp-lang"` (localStorage) — the language. Read at boot (A:31); written by the page switch `window.__lpSetLang`
  (A:272) **and** by the in-game settings page (which calls `LPWebSetLang` → `_LPWebSetLang` → `window.__lpSetLang`,
  A:25–28 / A:266). **[FACT]**
- Save game: IndexedDB via Unity (`autoSyncPersistentDataPath:true`, A:465) → `journey.json`; not localStorage. **[FACT: config; file name is [INFER] from the A:465 comment "journey.json"]**
- Unity web cache: IndexedDB `UnityCache_LittlePrince_小王子` (from `companyName`/`productName`; A:456–457). **[INFER from loader naming]**

## 6. Notable custom hardening (page bootstrap, layer a)

- **Extension-error shield** (A:375–401): capture-phase `error`/`unhandledrejection` listeners, registered *before*
  `loader.js`, drop events whose filename/stack names `*-extension://` or that are the cross-origin `"Script error."`
  with no filename. Reason (A:372–374): Unity's loader listens to every `window.onerror` and would reject
  `createUnityInstance` when, e.g., MetaMask/Phantom fight over `window.ethereum`.
- **`showBanner`** (A:468–473): Unity loader notices are routed — `error` → `showMessage` (UI), `warning`/other → console.
- **Message screen** `showMessage`/`drawMessage`/`failureText` (A:322–364): first failure kept on screen, detail rendered
  as text (never HTML), up to 6 stack lines; `__lpNet.failed` upgrades a generic error to the "network/blocked" wording (A:330).
- **`t()` / `percent()`** fall back to the fallback language when a string is missing (A:205–208).

## 7. Bottom line

- **Custom** = index.html head i18n + inline CSS + markup + bootstrap `<script>` + `LPWebLoading` (file B) + the three
  inline data blobs. Everything is same-origin and page-generated from `tools/shared/web/*`.
- **Unity-generated** = `Build/loader.js` (createUnityInstance) and `Build/framework.js.br` (Emscripten runtime, jslib
  merged). Neither contains any site-specific code except the 10 `LPWeb*` jslib functions Unity compiled in from the
  game's own `WebPlatform.jslib`.
- **Bridge** = 10 `env.LPWeb*` wasm imports, all UTF-8-string or numeric, exchanging state through `window.__lp*` globals
  and `localStorage["lp-lang"]`. The notable one-way custom entry is `LPWebGetLang`/`LPWebSetLang` for i18n round-trip
  between the page and the running game.
